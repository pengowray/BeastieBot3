IUCN dataset comparison — CSV vs API

Compares the IUCN Red List database (CSV release) with the IUCN API projection that iucn api project-view builds from the IUCN API cache. List and chart commands read the CSV release unless run with --dataset api.

Why the counts differ a little
  • Taxa with no current assessment in the IUCN API are left out of the API projection.
  • The IUCN API cache is downloaded over time, so some of its assessments can be from a different Red List release than the CSV release.
  • The API projection has subspecies and varieties only after iucn api cache-infraranks (iucn api cache-all --full runs it).
  • "partial" in the Coverage row: some current assessments are not downloaded yet.

    Taxa grouping

    Pick a Parent group and a Child rank, then Show counts for the number of species in each Red List category per sub-taxon (the same numbers as a parent list's summary table).

    Save sub-groups sets the parent's sub-groups in the draft taxa-groups.yml to the ticked rows. Sub-groups with no row in this table, such as ones with a system filter or at another rank, are removed. Apply the draft in the Rules editor.

    Define a new sub-group (e.g. a class like MAGNOLIOPSIDA)

    Create sub-group adds a taxa group to the draft taxa-groups.yml, and a list entry to the draft wikipedia-lists.yml so wikipedia generate-lists makes pages for it. To make it a sub-group of Parent, tick its row in the counts table and Save sub-groups; a group with no row there, such as one with a system filter, goes in the parent's children: list in the Rules editor. Then apply the draft in the Rules editor.

    • A taxon must match every filter.
    • Rank filter: is, any of or not; separate several values with commas.
    • System filter: IUCN systems separated by commas; a taxon in any of them matches (Marine, Freshwater selects aquatic taxa).
    • Inherit parent's filters copies the parent's rank filters, except ranks you set yourself. System filters are not copied.
    • ＋ define on a counts table row opens this panel with Key, Name and the first filter filled in.

    Rules editor

    Save draft saves your edits to the draft copy of the selected rule file; the Taxa grouping page saves its changes to the same draft. The files in rules/ change only when you click Apply changed files to source. Diff draft vs source shows every change before you apply it.

    Ways to get IUCN data

    ✓ the command adds this data; ~ part of it; + some species the CSV release lacks (see the + note below); · none of it.
    The API commands all add to the same IUCN API cache, so their results combine. iucn api cache-all --full runs them in one job and then builds the IUCN API projection.

    Option Species Subspecies & varieties Orphan subspecies † Removed / historical Rich content ‡ Ready to generate lists Requires
    iucn import (CSV release) ✓✓✓ ·~✓ manual zip download
    iucn api cache-all (taxa + assessments) ✓·· ·✓· API token; CSV (species list)
    iucn api discover-by-family +·· ✓✓· API token
    iucn api cache-infraranks (cached/API-sourced) ·✓· ·✓· API token; cached species
    iucn api cache-infraranks --from-csv ·✓✓ ·✓· API token; CSV
    iucn api cache-assessments (downloads queued payloads) ··· ·✓· API token
    iucn api project-view (build projection) ··· ··✓ — (local; needs the cache)
    iucn api cache-all --full (taxa + infraranks + assessments + projection) ✓✓✓ ·✓✓ API token; CSV

    + discover-by-family adds species the CSV omits (removed/historical/reclassified). † Orphan subspecies: an assessed subspecies or variety whose parent species has no IUCN assessment. Orphan subspecies can be downloaded from the API only by their own SIS IDs, which iucn api cache-infraranks --from-csv reads from the imported CSV release. ‡ Rich content: synonyms, narrative texts (such as the population narrative), population trends and assessment history (earlier assessments of each taxon) from the IUCN API. iucn import is marked ~ because the CSV release has the narrative texts and population trends, but no synonyms and only the current assessment of each taxon. "Ready to generate lists" means you can run generate-lists/charts afterwards (CSV via the default --dataset csv; the API cache only after project-view via --dataset api).
